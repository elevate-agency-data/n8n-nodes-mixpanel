# n8n-nodes-mixpanelapp  

This is an n8n community node. It lets you interact with Mixpanel in your n8n workflows.  

Mixpanel is a product analytics platform: it collects the events your users trigger in a website or an app, attaches them to user and group profiles, and answers questions on top of them with Insights, Funnels, Retention and cohorts. It also runs experiments and feature flags.

[n8n](https://n8n.io/) is a [fair-code licensed](https://docs.n8n.io/reference/license/) workflow automation platform.

## Installation  

Follow the [installation guide](https://docs.n8n.io/integrations/community-nodes/installation/) in the n8n community nodes documentation.  

Alternatively, you can manually install it:  

```sh  
git clone https://github.com/elevate-agency-data/n8n-nodes-mixpanel.git 
cd n8n-nodes-mixpanel 
npm install  
```  

Then, place the node file in the `~/.n8n/custom-nodes` directory (or follow instructions specific to your n8n installation).   

The npm package is named `n8n-nodes-mixpanelapp`, because `n8n-nodes-mixpanel` is already taken by another publisher.

This package is released under the MIT license. You can use it free of charge in commercial projects, client work, managed services and paid products, with no separate commercial license to buy.

## Credentials  

Every credential carries a **Region** field (*US*, *EU* or *India*) that must match the data residency of the project, shown in Project Settings. Mixpanel spreads its APIs over five hosts (`mixpanel.com/api/app`, `mixpanel.com/api/query`, `api.mixpanel.com`, `data.mixpanel.com`, `platform-us.mixpanel.com`), each with an EU and an India variant. The node picks the right one for every operation.

**Mixpanel Service Account API** is the recommended option, and the default. Create a service account in *Organization Settings > Service Accounts*, add it to the project, and enter its `Username`, its `Secret` (shown only once, at creation) and the `Project ID`. The node sends the project ID wherever an operation needs it, as `project_id` in the query string or as `{projectId}` in the path, so one credential covers one project. The credential test calls `GET /api/app/me`.

**Mixpanel Project Secret API** is for projects that still rely on the legacy API secret. It works for ingestion, export and the query API, but the management APIs (Annotations, Lexicon, Service Accounts, Experiments, Feature Flags, Warehouse Imports, Audit Logs) only accept a service account.

**Mixpanel GDPR API** is used by the *GDPR* resource, and by nothing else. The GDPR API is the only Mixpanel API authenticated by a personal OAuth token (`Authorization: Bearer`), generated by a project owner or admin, along with the project token.

## Project token and ingestion

*Track Events*, the *User Profile* and *Group Profile* update operations and *Identity* are authenticated by the **project token** inside each record, not by the credential. Set **Project Token** in the credential and the node adds it to every record that does not carry one (`properties.token` on events, `$token` on profiles and groups). *Evaluate Feature Flags* and *Get Feature Flag Definitions* also take it, in the query string.

These endpoints answer HTTP 200 even when they reject the data, unless `verbose=1` is set. The node sets it by default and fails the item when Mixpanel answers `"status": 0`. Be aware that Mixpanel accepts a **wrong project token** without any error: the data simply never shows up in the project.

For server-side and historical data, prefer *Event > Import Events* (`/import`). It is authenticated by the credential, accepts events older than 5 days, takes up to 2000 events per call, and runs in `strict=1` mode by default so that every invalid record is reported with its index. Each event needs `time`, `distinct_id` and `$insert_id` in its properties.

The bodies are JSON arrays of records, as in the Mixpanel reference. A single object is accepted too.

## Responses

Mixpanel does not always answer JSON. The node reads every response as text and turns it into items:

- JSON: one item, or one item per element of a top-level array.
- *Export Events* answers NDJSON, one event per line: one item per event. Use the `limit` query parameter, or short date ranges, on large projects.
- CSV (`format=csv` on some query operations): one item with the CSV in `data`.
- A bare `1` or `0` (ingestion without verbose): one item with `result`.

Form-encoded operations (*Data Pipeline* create, edit, delete, pause and resume, *Query Profiles*, *Run a JQL Query*) also take a JSON object in **Request Body**. Each key becomes a form field, and nested objects or arrays are sent as JSON strings, as Mixpanel expects. *Identity > Create an Identity* and *Create an Alias* send the JSON event as the `data` form field.

## Pagination and rate limits

This node does not paginate for you: it sends exactly one request per input item, so you stay in control of how many calls you make.

- **Query Profiles** pages with `page` and `session_id` in the request body: pass the `session_id` of the first response back with `page` incremented, until fewer results than `page_size` come back.
- **Query Audit Logs** pages with the `Cursor` query parameter.
- The **Query API** (Insights, Funnels, Retention, Segmentation, Event Breakdown, Cohorts, Query Profiles, JQL, Profile Activity) is limited to **60 queries per hour and 5 concurrent queries** per project.
- The **GDPR API** is limited to 1 request per second.
- **Import Events** accepts up to 2000 events or 10 MB per call.

To collect every page, wrap the node in a loop: a **Loop Over Items** node, or an **If** node testing whether the response still has results, feeding the value back into the Mixpanel node.

## Plan requirements

Some resources only answer when the matching feature is enabled on your Mixpanel plan. Mixpanel answers HTTP 402 otherwise, which the node reports as a plan limit.

- **Query API** (Insight, Funnel, Retention, Segmentation, Event Breakdown): Growth or Enterprise plan. On the Free plan, *Export Events* and *Query Profiles* remain available to read data.
- **Data Pipeline**: the Data Pipelines add-on. Without it, Mixpanel answers HTTP 401 `authorization failed`, even with valid credentials.
- **Warehouse Import**: Warehouse Connectors.
- **Experiment** and **Feature Flag**: available on the Free plan since August 2026, with limits (10 active feature flags, 1k monthly experiment users). Mixpanel refuses to delete an enabled flag: set its status to disabled with *Update a Feature Flag* first. Both need a workspace ID, found in the project URL: `/project/PROJECT_ID/view/WORKSPACE_ID/`.
- **Identity**: only meaningful on projects still on the *original* ID merge API. Projects on Simplified ID Merge link identities through `$device_id` and `$user_id` on regular events instead.
- **JQL** and **Get Profile Activity** are in maintenance mode on Mixpanel's side.

## Using as a Tool

This node can be used as a tool in n8n AI Agents. To enable community nodes as tools, you need to set the `N8N_COMMUNITY_PACKAGES_ALLOW_TOOL_USAGE` environment variable to `true`.

### Setting the Environment Variable

**If you're using a bash/zsh shell:**
```bash
export N8N_COMMUNITY_PACKAGES_ALLOW_TOOL_USAGE=true
n8n start
```

**If you're using Docker:**
Add to your docker-compose.yml file:
```yaml
environment:
  - N8N_COMMUNITY_PACKAGES_ALLOW_TOOL_USAGE=true
```

**If you're using the desktop app:**
Create a `.env` file in the n8n directory:
```
N8N_COMMUNITY_PACKAGES_ALLOW_TOOL_USAGE=true
```

**If you want to set it permanently on Mac/Linux:**
Add to your `~/.zshrc` or `~/.bash_profile`:
```bash
export N8N_COMMUNITY_PACKAGES_ALLOW_TOOL_USAGE=true
```

## Compatibility  

- Tested with: n8n 1.120.4 (self-hosted), Mixpanel Free plan, EU data residency

The 106 operations are built from the Mixpanel OpenAPI specifications, and all of them were run against a live project on the Free plan:

- **Answered with real data**: service accounts, event import and export, user profiles (verified with *Query Profiles*), Lexicon schemas, annotations, feature flags, experiments, GDPR requests, audit logs, and the lists of lookup tables and warehouse imports.
- **Accepted, effect not verifiable on Free**: group profiles (Group Analytics add-on) and Identity (only effective on Original ID Merge projects).
- **Refused by the plan, as expected**: the Query API (HTTP 402), Data Pipelines (HTTP 401) and warehouse import creation (HTTP 403). These requests are built from the specification but have not returned data yet.
- **Not run**: *Delete All Schemas*, which empties the Lexicon of the project.

Two things sit on your own project rather than on the node. A service account only reaches the projects it was added to, with the role it was given, so a 403 almost always means a missing membership or role (Annotations writes need at least Analyst). And an EU or India project only answers on its own region's hosts, so a 401 on a valid service account usually means the wrong Region in the credential. Data Pipelines is the exception: it answers 401 when the add-on is missing.
